============================================================
A) COSA CAMBIA NEL SITO
============================================================
In alto trovi tre rettangoli curvi uguali nello stile:
    [ Staff Zone ] [ Discord ] [ Carrello ]

Discord:
- se non autenticato: "Discord • Accedi";
- dopo OAuth: mostra avatar + nome Discord;
- cliccandolo da autenticato apre profile.html.

profile.html mostra:
- avatar Discord;
- username / global name;
- Discord ID reale;
- stato account;
- numero script acquistati;
- libreria personale con i download assegnati dallo staff.

============================================================
B) DISCORD DEVELOPER PORTAL
============================================================
Usa preferibilmente LA STESSA applicazione Discord del bot.

Developer Portal → tua applicazione → OAuth2.

Copia:
    Client ID

Genera/copia:
    Client Secret

NON mettere il Client Secret su GitHub.

Dopo aver creato il Worker Cloudflare, aggiungi in OAuth2 Redirects:
    https://TUO-WORKER.workers.dev/auth/callback

Deve essere identico al DISCORD_REDIRECT_URI configurato nel Worker.

Il login richiede solamente:
    identify

L'utente autorizza quindi la stessa applicazione Discord del bot per leggere
ID, username e avatar di base.

============================================================
C) FIREBASE SERVICE ACCOUNT
============================================================
Firebase Console → Project settings → Service accounts.

Genera una nuova private key JSON.

Dal JSON servono:
    client_email
    private_key

NON caricare il JSON su GitHub.

Nel Worker Cloudflare imposta come Secrets:
    FIREBASE_SERVICE_ACCOUNT_EMAIL = client_email
    FIREBASE_PRIVATE_KEY = private_key

============================================================
D) CLOUDFLARE WORKER — NON SERVE HOSTING A PAGAMENTO
============================================================
Crea un account Cloudflare se non ne hai uno.

Workers & Pages → Create → Worker.

Incolla:
    cloudflare-worker/worker.js

Deploy.

Prendi il suo URL, ad esempio:
    https://demon-leaks-auth.nomeaccount.workers.dev

Worker → Settings → Variables and Secrets.

Secrets:
    DISCORD_CLIENT_ID
    DISCORD_CLIENT_SECRET
    FIREBASE_SERVICE_ACCOUNT_EMAIL
    FIREBASE_PRIVATE_KEY

Variables:
    SITE_URL = https://demonleaks.xyz
    DISCORD_REDIRECT_URI = https://TUO-WORKER.workers.dev/auth/callback

Poi nel sito apri firebase-config.js e cambia:
    DISCORD_AUTH_BASE_URL: "https://INSERISCI-WORKER.workers.dev"

con il vero URL Worker.

============================================================
E) FIRESTORE RULES
============================================================
Firebase → Firestore Database → Rules.

Sostituisci TUTTO con firestore.rules di questo pacchetto e premi Publish.

Le regole consentono:
- products/settings pubblici in lettura;
- Staff Zone in scrittura tramite demonleaks@gmail.com;
- ogni Discord user può leggere/modificare soltanto il proprio profilo;
- ogni Discord user può leggere soltanto i propri acquisti;
- soltanto staff può assegnare acquisti;
- ogni Discord user può leggere soltanto il proprio eventuale blocco;
- privateProducts resta staff-only.

============================================================
F) REGISTRARE UN ACQUISTO
============================================================
Staff Zone → Utenti / Acquisti.

L'utente compare automaticamente dopo il primo login Discord.

Premi + accanto all'utente oppure "Registra acquisto".

Inserisci:
    Discord ID
    Script
    Nota opzionale

Per PREMIUM:
il sistema legge il link da privateProducts e lo copia nella libreria privata
dell'utente.

Il cliente apre:
    https://demonleaks.xyz/profile.html

e trova lo script in "I miei script".

============================================================
G) BLOCCARE UN UTENTE
============================================================
Staff Zone → Utenti / Acquisti → pulsante ⊘
oppure:
Staff Zone → Persone bloccate.

Il blocco usa il Discord ID reale.

Se quel profilo è autenticato sul sito:
- il sito mostra ACCESSO BLOCCATO;
- il profilo personale non mostra la libreria;
- può soltanto uscire da Discord.

============================================================
H) SICUREZZA
============================================================
NON mettere mai nel repository:
- DISCORD_CLIENT_SECRET
- Firebase service account JSON/private_key
- bot token
- webhook privati
- password staff

Il firebaseConfig Web resta pubblico come previsto da Firebase.

Il Worker usa Authorization Code Grant Discord con state anti-CSRF.
Il token Discord viene usato solo per leggere /users/@me e non viene salvato.
Il browser riceve un Firebase Custom Token, lo scambia con Firebase Auth e lo
rimuove immediatamente dall'URL.

============================================================
I) NOTA "APP AUTORIZZATA"
============================================================
Il pulsante Discord autorizza l'APPLICAZIONE Discord associata al bot.
Se usi Client ID/Secret della stessa app del bot, l'utente sta autorizzando
quella stessa applicazione. Lo scope identify serve all'identificazione del
profilo e NON concede accesso a messaggi privati o password Discord.
